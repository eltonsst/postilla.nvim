OVERVIEW                                          *postilla-overview*

postilla.nvim helps you leave local inline review comments while reviewing
changes made by coding agents. Comments are stored outside source files and are
shown with virtual text markers such as:
>
  💬 R1. Consider extracting this...
<
When the review is done, postilla.nvim builds RevDiff-compatible annotations,
copies them to the system clipboard, and saves a backup below:
>
  stdpath("state")/postilla/projects/
<
Each project gets a separate directory. Use :PostillaStatus to show the exact
active session path.

==============================================================================
REQUIREMENTS                                      *postilla-requirements*

- Neovim 0.10 or newer
- Git is optional, but recommended for project-relative paths
- Clipboard support is optional, but recommended for :PostillaDone

If Git is unavailable or the current file is outside a Git repository,
postilla.nvim falls back to Neovim's current working directory when building
relative file paths.

If clipboard support is unavailable, :PostillaDone still writes the generated
annotations under Neovim's state directory.

==============================================================================
SETUP                                             *postilla-setup*

With lazy.nvim:
>
  {
    "eltonsst/postilla.nvim",
    config = function()
      require("postilla").setup({
        keymap = "<leader>rc",
        next_keymap = "]r",
        previous_keymap = "[r",
      })
    end,
  }
<
Default configuration:
>
  require("postilla").setup({
    context_lines = 5,
    keymap = nil,
    next_keymap = nil,
    previous_keymap = nil,
    state_dir = nil,
    marker = {
      style = "virtual_line",
    },
    comment_window = {
      layout = "bottom",
      height = 10,
      width = 80,
    },
  })
<
Options:

                                                        *postilla-context_lines*
context_lines~
    Number of lines captured before and after the reviewed line.

                                                        *postilla-keymap*
keymap~
    Optional Normal- and Visual-mode mapping for :PostillaComment.

						*postilla-next_keymap*
next_keymap~
    Optional Normal-mode mapping for :PostillaNext.

						*postilla-previous_keymap*
previous_keymap~
    Optional Normal-mode mapping for :PostillaPrev.

                                                        *postilla-state_dir*
state_dir~
    Optional override for Postilla's Neovim state directory.

						*postilla-marker*
marker~
    Configures saved comment markers. style accepts "virtual_line" (the
    default) or "eol".

						*postilla-comment_window*
comment_window~
    Configures the comment editor. layout accepts "bottom" (the default) or
    "float". height controls the split or floating-window height. width is
    used by the floating layout.

==============================================================================
COMMANDS                                          *postilla-commands*

                                                        *:PostillaStart*
:PostillaStart~
    Start a review session. If saved state exists for the current project,
    restore the previous session. Legacy .local-review state is migrated.

                                                        *:PostillaComment*
:PostillaComment~
    Open a markdown scratch buffer for a review comment at the current line or
    selected range. By default it uses a bottom split so the reviewed code
    stays visible. Press <C-s> to save or <Esc> in normal mode to cancel.

    When the configured keymap is used in Visual mode, the comment is attached
    to every selected line. Character and block selections expand to complete
    lines. The command also accepts an explicit Ex range:
>
  :10,15PostillaComment
<

                                                        *:PostillaDone*
:PostillaDone~
    Generate RevDiff-compatible annotations, copy them to the + register, write
    a backup below Neovim's state directory, clear markers, and remove the
    session backup.

						*:PostillaExport*
:PostillaExport~
    Generate, copy, and save the same output as :PostillaDone, but keep the
    active review and its comments.

						*:PostillaPreview*
:PostillaPreview~
    Open the generated feedback in a bottom split. Press <CR> on a record to
    jump to its source, <C-s> to copy the output, or q to close the preview.

                                                        *:PostillaAbort*
:PostillaAbort~
    Clear the current review session and remove its backup without generating
    annotation output.

                                                        *:PostillaStatus*
:PostillaStatus~
    Show whether a session is active, how many comments are stored, and the
    latest comment location and state path.

                                                        *:PostillaList*
:PostillaList~
    Populate and open the quickfix list with one item per stored review
    comment.

						*:PostillaNext*
:PostillaNext~
    Jump to the next review comment in file and line order. Wraps at the end.

						*:PostillaPrev*
:PostillaPrev~
    Jump to the previous review comment. Wraps at the beginning.

                                                        *:PostillaEdit*
:PostillaEdit {id}~
    Reopen the markdown comment editor for an existing comment, for example:
>
  :PostillaEdit R1
<
                                                        *:PostillaDelete*
:PostillaDelete {id}~
    Delete a stored comment and clear its virtual text marker, for example:
>
  :PostillaDelete R1
<

==============================================================================
WORKFLOW                                          *postilla-workflow*

Typical flow:
>
  :PostillaStart
  :PostillaComment
  :PostillaPreview
  :PostillaDone
<
The generated output uses RevDiff record headers. Comments on normal working
buffers are emitted as context annotations:
>
  ## lua/postilla/init.lua:42 ( )
  Please simplify this branch.
<

Postilla uses extmarks while Neovim is open, so comments follow inserted and
deleted lines. Restored sessions locate the exact reviewed text again and use
its saved context to resolve duplicates. A warning marker means that the text
changed or its location is ambiguous. Preview and export are blocked until the
stale comment is deleted and recreated.

==============================================================================
HEALTHCHECK                                       *postilla-health*

Run:
>
  :checkhealth postilla
<
The healthcheck verifies:

- Neovim 0.10+
- git executable availability
- clipboard provider availability
- Postilla state directory

==============================================================================
MIGRATION                                         *postilla-migration*

postilla.nvim is the new name of local-review.nvim. Update the plugin
specification to "eltonsst/postilla.nvim", require("postilla"), and use
commands with the Postilla prefix.

The legacy local_review module and LocalReview commands are not retained.
Valid files under .local-review/ are migrated into Neovim's state directory
the first time :PostillaStart runs for a project.
